# Git Commit 規則

格式:`[Tag] 描述`

| Tag | 用途 |
|---|---|
| `[Feat]` | 新功能 |
| `[Fix]` | 修 bug |
| `[Docs]` | 文件、註解 |
| `[Data]` | 資料更新 |
| `[Refactor]` | 重構,不改行為 |
| `[Minor]` | 雜項小調整(設定、格式、依賴等不屬於上面任何一類的) |
| `[Auto]` | `daily-check` 自動產生的 commit,人工 commit 不使用 |

## 規則

1. 一個 commit 只用一個標頭、只做一件事
2. 標頭 + 描述不超過 50 字元(中文約 25 字),上限 72
3. 動詞開頭,說明做了什麼,結尾不加句號
4. 避免「修改」「update」這類沒資訊量的描述
5. 需要解釋原因時,空一行寫在內文

## 範例

```
[Feat] 新增使用者匯出 CSV 功能
[Fix] 修正日期欄位時區錯誤
[Docs] 補充安裝步驟說明
[Data] 更新 2026 Q3 銷售資料
[Minor] 統一縮排為 2 空格
[Auto] add closures: 兩館 2026-11-28 投票日
```
